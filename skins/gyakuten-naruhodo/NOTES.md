# 逆转裁判 · 成步堂龙一「异议」（动态）— 修复记录

| 项目 | 内容 |
| :-- | :-- |
| 原始文件 | `成步堂龙一 异议(动态) by雪泽歌子.ssf` |
| 原作者 | 雪泽歌子（`skin.ini` 内署名，2024.02.21） |
| 皮肤格式 | 老式 INI 皮肤（`skin.ini` + BMP/PNG/GIF 切片，UTF-16 LE 编码的 ini） |
| 包内文件 | 34 个，约 124 KB |

## 症状

输入 `v` 进入 v 模式后，弹出的面板是**白色背景 + 白色文字**，候选词几乎不可见；竖排候选窗同样如此。横排状态下的正常输入则显示正常（深红法庭背景 + 白字）。

## 根因

搜狗 INI 皮肤把候选窗拆成「横排」和「竖排」两套独立方案，各自引用不同底图：

| 方案 | 使用场景 | 底图 | 原底色 |
| :-- | :-- | :-- | :-- |
| `[Scheme_H1]` | 横排单行（日常输入） | `skin1.gif` 463×200 | 深红法庭 + 成步堂立绘 |
| `[Scheme_H2]` | 横排双行 | `skin2_1.bmp` + `skin1_2.bmp` | 浅蓝白 |
| `[Scheme_V1]` | 竖排单行 | `skin2.bmp` 29×142 | 白色渐变 |
| `[Scheme_V2]` | 竖排双行（**v 模式面板走这套**） | `skin2_1.bmp` + `skin2_2.bmp` | 白色 |

而文字颜色在 `[Display]` 段里是全局设置的，不区分横竖排：

```ini
pinyin_color=0xffffff
zhongwen_color=0xffffff
```

作者只给横排做了深色底图，竖排那几套沿用了搜狗的默认浅色模板，于是白字压在白底上。

其中 `skin2_1.bmp`（28×27）原本是那个橘色「S」图标，被当作 `pinyin_pic` 横向拉伸成整条拼音行背景，所以 v 模式面板顶部会出现一大片浅色区域 + 右侧一个被拉大的 S。

## 改动

只改颜色，不动任何尺寸、九宫格参数（`layout_*` / `*_marge`）和文字色，最大程度保证渲染逻辑不变：

| 文件 | 改动 |
| :-- | :-- |
| `skin2.bmp` | 白色渐变底 → 深蓝（主色 `#223255`，保留顶部 S 装饰） |
| `skin2_1.bmp` | 浅蓝白底 → 深蓝竖条纹，S 图标位置覆盖为同色系 |
| `skin2_2.bmp` | 纯白竖条 → 深蓝竖条纹 |
| `skin.ini` | `separator` 由 `0xCBCBCB` 调整为 `0x7EA0DF`（浅蓝分隔线，配深蓝底） |

其余 30 个资源（状态栏图标、软键盘、菜单等）与 `skin1.gif` 一字未动。

配色采样：

```
背景主色  #223255   (34, 50, 85)
边框/亮部 #3F5583   (63, 85, 131)
分隔线    0x7EA0DF
```

## 已知限制

- **`[Scheme_H2]`（横排双行）未处理**：该方案仍使用浅底的 `skin2_1.bmp` + `skin1_2.bmp`。如果你的搜狗被设成「横向候选 + 双行显示」，仍会遇到浅底白字。修法同 `scheme_V2`，把 `skin1_2.bmp` 一并压暗即可。
- `skin_name` 保持原样（`逆转裁判成步堂龙一`），因此会**覆盖**已安装的原皮肤。若想两者共存，把 `skin.ini` 里的 `skin_name` 改成别的名字再打包。

## 复现修复

`.ssf` 就是 ZIP，直接改内部 BMP 即可，注意两点：

1. `skin.ini` 是 **UTF-16 LE + BOM** 编码，改完必须按原样写回，否则搜狗读不出皮肤名；
2. BMP 是 24 位、自下而上存储、行按 4 字节对齐，改写时要保持文件头与行跨度不变，只替换像素区。

改完用 `tools/ssf_tool.py pack` 重新打包即可。
